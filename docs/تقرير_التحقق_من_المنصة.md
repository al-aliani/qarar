## 2. أخطاء حرجة

### 2.1 فشل بناء Vite — `AuthModal.js`

**الملف:** `web/js/ui/AuthModal.js`

**الرسالة:**
```
[vite:build-import-analysis] Failed to parse source for import analysis because the content 
contains invalid JS syntax. If you are using JSX, make sure to name the file with the .jsx or .tsx extension.
```

**الوصف:**  
مكوّن تحليل الاستيراد في Rollup/Vite يفشل في تحليل هذا الملف. المحتوى جافاسكربت عادي (بدون JSX) ويتضمّن قالب HTML كبير داخل template literal مع `${...}`.

**ما تم تجربته:**
- استبدال `</` بـ `\u003c/` في القالب — بدون تحسّن.
- إزالة تعليقات HTML `<!-- ... -->` — بدون تحسّن.

**احتمال السبب:**  
تحسّس المحلّل (acorn/rollup) لوجود تسلسلات مثل `</` أو `<div` داخل template literal واعتبارها شبه-JSX.

**التوصيات:**
1. **التطوير:** استخدام `npm run dev` — وضع التطوير يعتمد على esbuild وقد لا يطبق نفس تحليل الاستيراد الصارم.
2. **الإنتاج:**
   - نقل HTML إلى دالة تُركّب النص بـ `createElement` أو `['<div...', '></div>'].join('')` بدل template literal طويل، أو
   - استخراج القالب إلى ملف منفصل (مثلاً `.html` أو `.txt`) وقراءته أو استيراده كـ raw.
3. **استثناء مؤقت:** إذا احتجت نشرًا سريعًا، يمكن جعل `AuthModal` يُحمّل من مسار خارج حزمة Vite (مثلاً script منفصل) بحيث لا يمرّ على plugin تحليل الاستيراد نفسه — مع مراعاة تعقيدات التحميل والمسار.

## 4. هيكل التطبيق والاستيرادات

### 4.1 نقطة الدخول

- **الجذر:** `web/` (من `vite.config.js`: `root: './web'`).
- **الدخول:** `web/index.html` → `web/app.js`.

### 4.2 استيراد النموذج المالي

- **في `app.js`:**  
  `import { runFullModel } from '../lib/calc/financialModel.js';`
- من `web/app.js` المسار `../lib` يشير إلى `lib/` في جذر المشروع.
- **التحقق:** `lib/calc/financialModel.js` موجود وتصديراته متوقعة (مثل `runFullModel`).

### 4.3 الاستيراد الديناميكي لـ AuthModal

- **من:** `Sidebar.js`، `DashboardView.js`  
  `const { AuthModal } = await import('./AuthModal.js');`
- المسار صحيح ضمن `web/js/ui/`. المشكلة في **تحليل** الملف عند البناء وليست في مسار الاستيراد.

### 4.4 Supabase و AuthModal

- **في AuthModal:**  
  `const { signIn, signUp } = await import('../../supabaseClient.js');`
- من `web/js/ui/` يصبح الهدف `web/supabaseClient.js` — الملف موجود ويصدّر الدوال المطلوبة.

## 5. الملفات والمكوّنات المُراجعة

| الملف / المجلد | ملاحظات |
|----------------|---------|
| `web/app.js` | استيرادات ونقاط `navigateTo` للمكوّنات المخصّصة سليمة. |
| `web/index.html` | CSP، الخطوط، السكربتات، ووجود `wizardContainer` و`stepperNav` ومناطق التصدير والهواتف. |
| `web/js/core/schema.js` | استخدام `SECTIONS` و`TABLE_SCHEMAS` متوافق مع `app.js` و`Wizard`. |
| `web/js/ui/Wizard.js` | يتعامل مع خطوة `marketing` (جداول + رسم بياني)، و`store.get()` — يُفترض توافقه مع `store.getState()` إن وُجد. |
| `web/js/services/InternalAIGenerator.js` | دوال التوليد (PESTEL, Porter, SWOT, Segments, Competitors, …) مصدّرة ومتصلة بالواجهات. |
| `web/js/ui/StrategicAnalysis.js` | أزرار التوليد التلقائي لـ PESTEL, SWOT, Porter مربوطة. |
| `web/js/ui/MarketAnalysis.js` | أزرار التوليد التلقائي لـ TAM-SAM-SOM، شرائح العملاء، مصفوفة المنافسين مربوطة. |
| `web/js/ui/AuthModal.js` | منطق الواجهة والربط مع `supabaseClient` سليم؛ المشكلة في **تحليل البناء** فقط. |
| `vite.config.js` (جذر المشروع) | `root: './web'`، `/lib`، خادم التطوير، `/assets`، الـ proxy لـ `/api` — متسقة مع هيكل المشروع. |
