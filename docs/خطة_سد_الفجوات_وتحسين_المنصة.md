# خطة سد الفجوات وتحسين منصة محاكي الجدوى

**المرجع:** تقرير الفجوة بين المنصة واللقاءات التدريبية  
**تاريخ الإعداد:** يناير 2025  
**حالة التنفيذ:** ✅ مكتمل (يناير 2025)

---

## نظرة عامة

الخطة مقسمة إلى **4 مراحل** بحسب الجهد والأثر:

| المرحلة | المحتوى | الجهد التقريبي | الأثر |
|---------|---------|----------------|-------|
| **المرحلة 1** | تنبيهات وإرشادات (بدون تغيير بنية البيانات) | 1–2 أيام | متوسط |
| **المرحلة 2** | إضافة حقول وواجهات بسيطة | 3–5 أيام | عالي |
| **المرحلة 3** | ميزات جديدة (توازن العرض والطلب، مصادر البيانات، بطاقة المنح) | 5–8 أيام | عالي جداً |
| **المرحلة 4** | تحسينات متقدمة (دراسة مبدئية، نموذج مصغر، عقود شراكة) | 5–7 أيام | متوسط |

## المرحلة 1 — تنبيهات وإرشادات (بدون تغيير بيانات)

**الهدف:** تعزيز تجربة المستخدم وإبراز ممارسات يوصي بها المدربون دون تعديل السكيم.

### 1.1 إضافة بطاقات/تنبيهات في الواجهة

| المهمة | الموقع | النص المقترح |
|--------|--------|--------------|
| تنبيه تحليل الحساسية | خطوة تحليل الحساسية أو الملخص التنفيذي | "تحليل الحساسية إلزامي — أي دراسة بدونه تعتبر غير مكتملة" |
| إرشاد رأس المال العامل | خطوة الافتراضات أو مصادر التمويل | "رأس المال العامل حاسم — إهماله سبب رئيسي لأزمات السيولة" |
| تنبيه الدراسة ليست مضمونة | المقدمة أو الملخص التنفيذي | "الدراسة قد تخضع للمتغيرات — المستقبل مجهول، والمتغيرات قد تتغير" |
| تنبيه لا استقالة | المقدمة أو شاشة البداية | "لا تستقيل من الوظيفة إلا بعد إكمال دراسة جدوى حقيقية ومتكاملة" |
| إرشاد صاحب المشروع مصدر المعلومات | المقدمة | "أنت المصدر الرئيسي للمعلومات — لا تترك مكاتب الاستشارات تختلق البيانات دون مراجعتك" |
| تنبيه نسبة فشل المشاريع (80%) | المقدمة أو الملخص | "نسبة فشل المشاريع الصغيرة قد تصل 80% — الدراسة الجيدة تخفّف المخاطر" |

**الملفات المتوقعة:** `Wizard.js`, `IntroductionView.js`, `ExecutiveSummary.js`, `SensitivityAnalysis.js`

### 1.2 إرشادات تسويقية

| المهمة | الموقع | النص المقترح |
|--------|--------|--------------|
| تسعير قريب من المنافس | قسم المزيج التسويقي (Price) | "لا حرب أسعار — اجعل السعر قريباً من المنافسين، لا أقل بكثير ولا أعلى بكثير" |
| تجنب "جميع فئات المجتمع" | قسم شرائح العملاء | "حدد شريحة واضحة — تجنب عبارة 'جميع فئات المجتمع'" |
| الحملة حسب الشريحة | قسم الحملات | "إذا منتجك لفئة 20% فقط، لا تعمل حملة واسعة لكل الناس" |

**الملفات المتوقعة:** `MarketAnalysis.js`, `Wizard.js`

### 1.3 توضيح الفروقات (للمستخدم)

| المهمة | الموقع | النص المقترح |
|--------|--------|--------------|
| السوقية vs التسويقية | قسم تحليل السوق | "السوقية: المستهلكون والمنافسون. التسويقية: كيف تسوّق (المزيج التسويقي)" |
| الدراسة vs الاختبار الأولي | المقدمة أو قسم النتائج | "الدراسة تقول ابدأ أم لا؛ الاختبار الأولي يتعلم من التجربة في السوق" |

## المرحلة 2 — إضافة حقول وواجهات بسيطة

**الهدف:** إكمال السكيم والواجهات بحقول مذكورة في التقرير ولا تتطلب محركاً جديداً.

### 2.1 التقسيم الجغرافي للسوق

| المهمة | التفاصيل |
|--------|----------|
| حقل "المنطقة المستهدفة" / "الحي" | إضافة في `projectInfo` أو `marketSizing`: `targetDistrict`, `targetNeighborhood` |
| إرشاد جغرافي | "إذا مستهدفك شرق الرياض، لا تدرس منافسي غرب الرياض" |
| ربط بالمدينة | تعزيز `projectInfo.city` و `district` إن وُجد |

**الملفات:** `schema.js`, `IntroductionView.js` أو `MarketAnalysis.js`, `wizardSteps.js`

### 2.2 اتجاهات الطلب التاريخية (5 سنوات)

| المهمة | التفاصيل |
|--------|----------|
| إبراز `historicalData` | الحقل موجود في `marketing.marketAnalysis` — إضافته لواجهة تحليل السوق |
| جدول بسيط | سنة، الطلب/الحجم، ملاحظات |
| إرشاد | "دراسة اتجاه الطلب خلال 5 سنوات على الأقل — الاتجاه الصاعد إيجابي" |

**الملفات:** `MarketAnalysis.js`, `Wizard.js` (إذا كان جدول ديناميكي), `sectionExporter.js`

### 2.3 شرائح العملاء — حقول إضافية

| المهمة | التفاصيل |
|--------|----------|
| تردد الشراء | إضافة في segment: `purchaseFrequency` (يومي / أسبوعي / شهري / نادراً) |
| طريقة الشراء | إضافة: `purchaseMethod` (نقدي، إلكتروني، توصيل، تطبيق) |

**الملفات:** `schema.js`, `MarketAnalysis.js` أو مكون الشرائح, `sectionExporter.js`

### 2.4 عقود الشراكة

| المهمة | التفاصيل |
|--------|----------|
| قسم جديد | `partnershipContracts` أو ضمن `keyPeople`: من قام بماذا، توزيع الصلاحيات، عقد تأسيس |
| حقول | أسماء الشركاء، الأدوار، النسب، ملاحظات |

**الملفات:** `schema.js`, `IntroductionView.js` أو مكون جديد, `wizardSteps.js`, `ReportGenerator.js`, `sectionExporter.js`

### 2.5 حقل المبرر لتثبيت/تغيير المبيعات

| المهمة | التفاصيل |
|--------|----------|
| حقل في الافتراضات أو مصادر الإيرادات | `revenueGrowthJustification` أو `salesAssumptionNotes` |
| إرشاد | "وضح لماذا المبيعات ثابتة أو متزايدة أو متناقصة" |

**الملفات:** `schema.js`, `Wizard.js` أو `RevenueView.js`, `ReportGenerator.js`

## المرحلة 3 — ميزات جديدة (أولوية عالية)

**الهدف:** سد الفجوات ذات الأثر الأعلى على موثوقية الدراسة.

### 3.1 تحليل توازن العرض والطلب

| المهمة | التفاصيل |
|--------|----------|
| قسم جديد | `supplyDemandBalance` ضمن تحليل السوق |
| حقول مقترحة | `estimatedSupply`, `estimatedDemand`, `balanceConclusion` (فرصة / خطر / محايد), `notes` |
| واجهة | بطاقة أو جدول بسيط + إرشاد: "الطلب > العرض = فرصة؛ العرض > الطلب = خطر" |
| تضمين في التقرير | قسم في الملخص أو تحليل السوق |

**الملفات:** `schema.js`, `MarketAnalysis.js`, `wizardSteps.js`, `ReportGenerator.js`, `sectionExporter.js`

### 3.2 قائمة مصادر البيانات الرسمية السعودية

| المهمة | التفاصيل |
|--------|----------|
| مكون جديد أو قسم في المقدمة | قائمة ثابتة بمصادر: GASTAT، الغرفة التجارية، الغرفة الصناعية، معهد الإدارة العامة |
| روابط | روابط لمواقع الجهات (إن أمكن) |
| ربط اختياري بالحقول | اقتراح مصدر لكل نوع بيانات (مثلاً: التعداد ← GASTAT) |

**الملفات:** مكون جديد `DataSourcesGuide.js` أو قسم في `IntroductionView.js`, `ReportGenerator.js`

### 3.3 قالب/تصدير "بطاقة منح" (بنك التنمية)

| المهمة | التفاصيل |
|--------|----------|
| قالب تصدير | PDF أو Excel بصيغة مبسطة: اسم المشروع، موقع، أهداف، تكاليف، إيرادات، مدة استرداد |
| توافق | متوافق مع متطلبات بنك التنمية الاجتماعية |
| تنبيه | "التعبئة من الحاسوب — راجع البيانات قبل الإرسال" |

**الملفات:** `ReportGenerator.js` أو مكون جديد `GrantCardExporter.js`, `excelExporter.js`

### 3.4 إرشاد ربط الحقول بالمصادر

| المهمة | التفاصيل |
|--------|----------|
| اقتراحات سياقية | عند حقل التعداد: "المصدر المقترح: الهيئة العامة للإحصاء" |
| عند حقل القطاع: "المصدر المقترح: الغرفة التجارية/الصناعية" |

**التنفيذ:** tooltips أو نصوص مساعدة بجانب الحقول المختارة

## المرحلة 4 — تحسينات متقدمة

**الهدف:** تحسين التوجيه والمرونة دون تعقيد الواجهة.

### 4.1 مرحلة "دراسة مبدئية"

| المهمة | التفاصيل |
|--------|----------|
| وضع أو وضعية | "وضع مبدئي" يطرح أسئلة مختصرة: هل المشروع ممكن؟ مناسب للبيئة؟ |
| صفحة تأهيلية | 3–5 أسئلة قبل الدخول للتفاصيل |
| اختياري | يمكن تخطيه للمستخدمين المتقدمين |

**الملفات:** `app.js`, مكون جديد `PreliminaryCheckView.js`, `wizardSteps.js`

### 4.2 نموذج مصغر للدراسة

| المهمة | التفاصيل |
|--------|----------|
| قالب "حد أدنى" | خطوات مختصرة: فكرة، سوق، تكاليف، إيرادات، قرار |
| توافق مع الجهات | الحد الأدنى المطلوب لبنك التنمية أو الغرفة |
| توجيه للمبتدئ | "هذا النموذج للمبتدئين — الحد الأدنى قبل التوجه لمتخصص" |

**الملفات:** `wizardSteps.js` (وضع مصغر), `TemplateSelector.js`, قالب JSON جديد

### 4.3 خيار الفرنشايز

| المهمة | التفاصيل |
|--------|----------|
| نوع مشروع | إضافة "فرنشايز" كخيار عند إنشاء مشروع |
| حقول إضافية | اسم العلامة، الشركة الأم، رسوم الامتياز، متطلبات العلامة |
| إرشاد | "الفرنشايز يحتاج دراسة جدوى أيضاً — المكان، الطلب، الملاءمة" |

**الملفات:** `schema.js`, `IntroductionView.js`, `wizardSteps.js`

### 4.4 تقدير مبيعات المنافس

| المهمة | التفاصيل |
|--------|----------|
| آلية اختيارية | عدد عملاء × متوسط فاتورة = مبيعات يومية تقديرية |
| حقل لكل منافس | `estimatedDailyCustomers`, `estimatedAvgTicket`, `estimatedDailyRevenue` |
| ربط بحصة السوق | استخدام الناتج في حساب SOM أو الحصة المتوقعة |

**الملفات:** `schema.js`, `MarketAnalysis.js`, `Wizard.js`

### 4.5 وصف العملية الإنتاجية

| المهمة | التفاصيل |
|--------|----------|
| حقل نصي أو منظم | وصف خطوات الإنتاج من المدخلات للمخرجات |
| إرشاد | "الوصف يساعد في تحديد الاحتياجات (عمالة، معدات، مواد)" |
| ربط بالدراسة الفنية | إظهار في قسم التقني إن وُجد |

**الملفات:** `schema.js`, مكون الدراسة الفنية

### 4.6 قائمة خطوات جمع المعلومات (زيارات ميدانية)

| المهمة | التفاصيل |
|--------|----------|
| قسم جديد | قائمة مهام: زيارة منافسين، جهات حكومية، جهات تمويل |
| checkbox أو جدول | خطوة، الحالة، ملاحظات |

**الملفات:** `schema.js`, مكون في المقدمة أو تحليل السوق

## ترتيب التنفيذ المقترح

```
الأسبوع 1–2:
├── المرحلة 1 (التنبيهات والإرشادات) — سريع، أثر فوري
└── المرحلة 2.2 (اتجاهات الطلب التاريخية) — الحقل جاهز، يحتاج واجهة فقط

الأسبوع 3–4:
├── المرحلة 2.1 (التقسيم الجغرافي)
├── المرحلة 2.4 (عقود الشراكة)
└── المرحلة 3.1 (توازن العرض والطلب)

الأسبوع 5–6:
├── المرحلة 3.2 (مصادر البيانات الرسمية)
├── المرحلة 2.3 (تردد الشراء، طريقة الشراء)
└── المرحلة 3.3 (بطاقة المنح) — إن أمكن

الأسبوع 7+:
├── المرحلة 4 (التحسينات المتقدمة) حسب الأولوية
└── مراجعة واختبار شامل
```
