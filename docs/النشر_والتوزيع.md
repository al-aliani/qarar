# النشر والتوزيع — Vercel / Netlify

> **المعايير المغطاة:** vercel.json/netlify.toml، Load balancing، CDN، Auto-scaling

---

## 1. ملفات النشر الجاهزة

| الملف | المنصة | الاستخدام |
|-------|--------|----------|
| `vercel.json` | Vercel | `vercel` أو ربط المستودع من لوحة Vercel |
| `netlify.toml` | Netlify | ربط المستودع من لوحة Netlify |

### النشر السريع

**Vercel:**
```bash
npm install -g vercel
vercel
```

**Netlify:**
```bash
npm run build
npx netlify deploy --prod --dir=web/dist
```

أو ربط مستودع Git من لوحة كل منصة؛ الملفات تُعرّف البناء والنشر تلقائياً.

---

## 2. Load Balancing (موازنة الحمل)

عند النشر على **Vercel** أو **Netlify**:

- **توزيع تلقائي:** الطلبات تُوزَّع على Edge Nodes حول العالم.
- **لا حاجة لإعداد يدوي:** المنصة تدير موازنة الحمل داخلياً.
- **للبنية التقليدية (خادم خاص):** راجع `docs/Load_Balancing_CDN.md` لإعداد Nginx أو موزع حمل سحابي.

---

## 3. CDN Configuration (إعداد CDN)

### ما يوفره Vercel و Netlify تلقائياً

- **توزيع محتوى Edge:** الملفات الثابتة تُقدَّم من أقرب نقطة للمستخدم.
- **رؤوس تخزين مؤقت:**
  - في `vercel.json`: رؤوس `Cache-Control: public, max-age=31536000, immutable` لـ `/assets/*`.
  - في `netlify.toml`: نفس الرؤوس لمجلد الأصول.

### الملفات المُخزَّنة

| المسار | المدة | الغرض |
|--------|-------|-------|
| `/assets/*` | سنة (immutable) | ملفات JS/CSS المُصدَّرة بـ hash |
| `index.html` | لا تخزين (أو قصير) | ضمان حصول المستخدم على آخر إصدار |

---

## 4. Auto-scaling (التوسع التلقائي)

- **Vercel / Netlify:** بنية **Serverless**؛ التوسع تلقائي حسب الطلب.
- لا حاجة لضبط عدد النسخ أو سعة الخوادم يدوياً.
- للمزيد عن البنية التحتية: `docs/Load_Balancing_CDN.md`.
