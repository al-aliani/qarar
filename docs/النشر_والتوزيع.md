## 1. ملفات النشر الجاهزة

Vercel هي منصة الاستضافة الفعلية الوحيدة حالياً. كان `netlify.toml` موجوداً
سابقاً، لكنه أُزيل نهائياً بتاريخ 2026-07-22 (commit `c05fbfc`) بوصفه ملفاً
يتيماً (لا نشر فعلي عبر Netlify) — التوثيق أدناه يعكس الواقع الحالي فقط.

| الملف | المنصة | الاستخدام |
|-------|--------|----------|
| `vercel.json` | Vercel | `vercel` أو ربط المستودع من لوحة Vercel |

### النشر السريع

**Vercel:**
```bash
npm install -g vercel
vercel
```

أو ربط مستودع Git من لوحة Vercel؛ `vercel.json` يُعرّف البناء والنشر تلقائياً.

## 2. Load Balancing (موازنة الحمل)

عند النشر على **Vercel**:

- **توزيع تلقائي:** الطلبات تُوزَّع على Edge Nodes حول العالم.
- **لا حاجة لإعداد يدوي:** المنصة تدير موازنة الحمل داخلياً.
- **للبنية التقليدية (خادم خاص):** راجع `docs/Load_Balancing_CDN.md` لإعداد Nginx أو موزع حمل سحابي.

## 3. CDN Configuration (إعداد CDN)

### ما يوفره Vercel تلقائياً

- **توزيع محتوى Edge:** الملفات الثابتة تُقدَّم من أقرب نقطة للمستخدم.
- **رؤوس تخزين مؤقت:**
  - في `vercel.json`: رؤوس `Cache-Control: public, max-age=31536000, immutable` لـ `/assets/*`.

### سياسة الكاش — القاعدة الحاكمة

`vercel.json` صيغة JSON صارمة لا تقبل تعليقات ولا مفاتيح إضافية داخل `routes`
(`additionalProperties: false` — أي `_comment` يُفشل الإعداد)، فالتوثيق هنا.

> **`immutable` لسنة يُمنح فقط لما لا يمكن تغييره دون تغيير اسمه**: إمّا اسم مبصوم
> بالمحتوى (hash)، أو ملف ثنائي لا يتبدّل إلا بترقية حزمة. أي ملف **إعداد** باسم ثابت
> يجب ألا يكون `immutable` أبداً — لا توجد وسيلة لإبطاله بعد النشر.

**ترتيب القواعد مقصود:** في `routes` الأخيرُ يفوز (`continue: true` يدمج الترويسات ثم
يستبدل المتكرِّر منها). لذلك تأتي القواعد العامة أولاً ثم الأضيق تصحّح فوقها — ولهذا
تحديداً تقع قاعدة `^/assets/(.*)$` **بعد** قواعد الصور/الخطوط العامة، وإلا لخفّضتها
هذه الأخيرة عن `immutable`. (مؤكَّد حيّاً على sahib.sa: `/sw.js` يطابق قاعدة `.js`
العامة ومع ذلك يعود بـ`must-revalidate` من القاعدة الأضيق التي تليها.)

| المسار | المدة | لماذا |
|--------|-------|-------|
| `/assets/*` | سنة `immutable` | اسم مبصوم بالمحتوى — أي تعديل يولّد اسماً جديداً |
| `*.woff2/woff/ttf/otf` | سنة + `stale-while-revalidate` | ثنائي لا يتغيّر إلا بترقية الحزمة، وهو preloaded فإعادة التحقق كانت تحجب أول رسم — لكن **بلا `immutable`**: أسماء الخطوط ليست مبصومة بالمحتوى (`ibm-plex-sans-arabic-arabic-400-normal.woff2`)، فلو استُبدل محتوى خط تحت نفس الاسم لتعذّر إبطاله لدى الزوار العائدين سنة كاملة. `swr` يمنح نفس الأداء مع مسار تعافٍ |
| `*.pdf/xlsx/xls/docx/csv` | 30 يوماً + `stale-while-revalidate` | كتالوج `/studies` (456 ملفاً ≈471MB) و`/databases` (≈20MB): محتوى مؤلَّف مسبقاً لا يُحرَّر بعد النشر، وكان يُعاد تنزيله كل زيارة |
| صور (`png/jpg/svg/webp/ico`) | 7 أيام + `stale-while-revalidate` | مثل `og-image.png`: مستقرّة لكنها قد تُحدَّث؛ المدة المتوسطة تُوصل التحديث خلال أسبوع بلا انتظار سنة |
| `/fonts/fonts.css` | يوم + `stale-while-revalidate` | يربط أسماء ملفات الخطوط؛ لو قُفل سنة لتعذّرت ترقية أي خط |
| `/js/*.js` | `max-age=0, must-revalidate` | سكربتات إقلاع بأسماء ثابتة بلا hash (theme-init, init-watchdog, cookie-notice, sw-register) تُحمَّل مباشرةً من الـHTML — لو قُفلت لما وصل إصلاح خطأ إقلاع لمن زار الموقع سابقاً |
| `/whatsapp-config.js` | `max-age=0, must-revalidate` | رقم واتساب الدعم: تغييره يجب أن يصل فوراً — عميل يتصل برقم قديم خسارة مباشرة |
| `/bank-transfer-config.js` | `max-age=0, must-revalidate` | بيانات التحويل البنكي: تحويل إلى حساب قديم خسارة مباشرة |
| `/sw.js` | `max-age=0, must-revalidate` | وإلا تجمّد إصدار التطبيق لدى المستخدم |
| `/manifest.json` | `max-age=0, must-revalidate` | إعداد PWA باسم ثابت |
| `index.html` وبقية HTML | الافتراضي: `max-age=0, must-revalidate` | ضمان حصول المستخدم على آخر إصدار — بلا قاعدة خاصة، وهو الصحيح |
| `/data/*.json`، sitemap، robots | الافتراضي: `max-age=0, must-revalidate` | كتالوجات ومسارات تتغيّر — الافتراضي صحيح، تُركت عمداً |

## 4. Auto-scaling (التوسع التلقائي)

- **Vercel:** بنية **Serverless**؛ التوسع تلقائي حسب الطلب.
- لا حاجة لضبط عدد النسخ أو سعة الخوادم يدوياً.
- للمزيد عن البنية التحتية: `docs/Load_Balancing_CDN.md`.
