### 2.1 تحميل دراسة من JSON دون انتظار الحفظ قبل إعادة التحميل

**الملف:** `web/app.js`  
**السطور:** 481–505

عند تحميل دراسة من ملف JSON:
- يتم تعيين `store.state = data` ثم `store.save()` ثم `store.notify()` ثم `location.reload()`.
- `store.save()` يستدعي `saveLocalDebounced()` مع تأخير **1 ثانية**.
- `location.reload()` يحدث فوراً، فتتم إعادة التحميل **قبل** أن يُكتب أي شيء إلى التخزين المحلي.
- **النتيجة:** البيانات المُحمّلة من الملف تُفقد بعد إعادة التحميل؛ المستخدم يرى الدراسة القديمة أو الفارغة.

**الإصلاح المقترح:**
- جعل `reader.onload` دالة `async`، وبعد التحقق من صحة الملف وقبل `location.reload()`:
  - تعيين `store.state = data`
  - استدعاء `await store.flush()` لضمان كتابة الحالة فوراً إلى التخزين
  - ثم `store.notify()` و`location.reload()`.

### 2.2 دوال DataService المُستدعاة غير موجودة — أخطاء وقت التشغيل

**الإصلاح المقترح:**

### 2.3 `configureServer` داخل `server` — مسار `/assets` لا يعمل

**الملف:** `vite.config.js` (الجذر)  
**السطور:** 16–44

الكود الحالي:

```js
server: {
  port: 5173,
  fs: { allow: ['..'] },
  proxy: { ... },
  async configureServer(server) {
    server.middlewares.use('/assets', ...);
  }
}
```

`configureServer` هو **خطاف (hook) خاص بمكون إضافي (Plugin)** وليس من خيارات `server` في Vite. خيارات `server` المعروفة (مثل `port`, `proxy`, `fs`) لا تتضمن `configureServer`.

**النتيجة:**  
الوسط البرمجي الخاص بـ `/assets` لا يُسجَّل، وطلبات مثل `/assets/...` ستُرجع 404 أثناء التطوير.

**الإصلاح المقترح:**  
نقل منطق `/assets` إلى مكوّن إضافي داخل `plugins`:

```js
import { defineConfig } from 'vite';
// ... resolve, __dirname, assetsDir

export default defineConfig({
  root: './web',
  resolve: { ... },
  server: { port: 5173, fs: { allow: ['..'] }, proxy: { ... } },
  plugins: [{
    name: 'serve-assets',
    configureServer(server) {
      server.middlewares.use('/assets', (req, res, next) => {
        // نفس المنطق الحالي من السطور 31–41
      });
    },
  }],
});
```

### 2.4 خريطة حقول خاطئة في Wizard للتراخيص والـ Smart Fill

**الملف:** `web/js/ui/Wizard.js`  
**السطور:** 268–296 (وبخاصة 286–295)

في «جلب التراخيص الحكومية» يُبنى `newData` كالتالي:

```js
newData = licenses.map(l => ({
  id: ...,
  name: l.name,
  cost: l.cost,        // ← لا يوجد عمود "cost" في TABLE_SCHEMAS.licenses
  renewYearly: true,
  isCapex: false
}));
```

بينما `TABLE_SCHEMAS.licenses` (في `schema.js`) يعرّف الأعمدة: `name`, `quantity`, `price`, `total` (محسوب: `quantity * price`), `notes`. لا يوجد `cost` ولا `renewYearly` ولا `isCapex` في التعريف.

**النتيجة:**  
حتى لو وُجِدت `DataService.getComplianceCosts` وأرجعت `{ name, cost }`، العمود `price` يبقى `undefined`، فيصبح `total = quantity * price = 0` ولا تظهر القيمة الصحيحة في الجدول.

**الإصلاح المقترح (عند تنفيذ `getComplianceCosts`):**

```js
newData = licenses.map(l => ({
  id: Date.now() + Math.random(),
  name: l.name,
  quantity: 1,
  price: l.cost ?? l.price ?? 0,
  notes: l.renewYearly ? 'تجديد سنوي' : ''
}));
```

وبالنسبة لـ `isCapex`: إما إضافتها إلى `TABLE_SCHEMAS.licenses` إن لزم، أو تجاهلها في الـ Smart Fill حالياً.

### 2.5 خريطة خاطئة لحقول projectInfo في Wizard (Smart Fill)

**الملف:** `web/js/ui/Wizard.js`  
**السطور:** 272–274

```js
const size = state.technical?.area || 100;           // ❌ technical لا يحتوي "area"
const type = state.projectInfo?.activity || 'cafe';  // ❌ projectInfo لا يحتوي "activity"
const city = state.projectInfo?.location || 'الرياض'; // ❌ projectInfo لا يحتوي "location"
```

وفق `schema.js`:

- `projectInfo`: `areaSize` (وليس `technical.area`)، `concept` (وليس `activity`)، `city` و`district` (وليس `location`).
- `technical`: لا يوجد `area`.

**النتيجة:**  
حتى مع وجود `DataService.recommendStaffing` و`getComplianceCosts`، ستُمرَّر قيم افتراضية خاطئة (مثل `size=100` دائماً، `type='cafe'`، `city='الرياض'`) بدل استخدام بيانات المستخدم.

**الإصلاح المقترح:**

```js
const size = state.projectInfo?.areaSize || state.technical?.areaSize || 100;
const type = state.projectInfo?.concept || 'cafe';
const city = state.projectInfo?.city || 'الرياض';
```

مع مراعاة اتساق أسماء الحقول مع باقي الـ schema.

### 2.6 تعيين مباشر لـ `store.state` عند التحميل من ملف

**الملف:** `web/app.js`  
**السطور:** 492–494

```js
store.state = data;
store.save();
store.notify();
```

`StudyStore` يعرّف `state` كخاصية عادية. التعيين المباشر `store.state = data` يتجاوز أي تحقق أو دمج مع الهيكل الافتراضي.

**المخاطر:**
- ملفات قديمة قد تفتقد `id` أو `projectInfo` أو أقساماً كاملة (`assumptions`, `revenue`, …).
- عدم دمج مع `createEmptyStudy()` قد يؤثر على `runFullModel` أو وحدات تعتمد على بنية كاملة (مثل التصدير إلى Excel/PDF).

**الإصلاح المقترح:**
- التحقق من وجود `data.id` و`data.projectInfo` (كما هو اليوم)، مع:
  - إسناد `data.id = data.id || crypto.randomUUID()` إذا وُجد `projectInfo` فقط.
  - دمج تلقائي مع `createEmptyStudy()` للأقسام المفقودة قبل تعيين `store.state`، ثم استدعاء `store.flush()` قبل `location.reload()` كما في 2.1.

### 3.1 `getAuthUser` من الـ store في Sidebar

**الملف:** `web/js/ui/Sidebar.js`  
**السطر:** 147

```js
const { user } = this.store?.getAuthUser?.() || {};
```

`store` لا يقدّم `getAuthUser`. `getAuthUser` مُصدَّر من `supabaseClient.js` وهو دالة **غير متزامنة**.

**النتيجة:**  
`user` يكون دائماً `undefined`، ويُعرض دائماً «● مسودة محلية» في الفرع `status.location === 'local'` حتى لو كان المستخدم مسجلاً. الفرع الذي يعرض «● جاري الحفظ...» أو «● خطأ في المزامنة» لا يُستخدم في الواقع.

**الإصلاح المقترح:**
- الاحتفاظ بـ `user` من سياق تسجيل الدخول (مثلاً عند `updateAuthWidget` أو عند استدعاء `getAuthUser` من `supabaseClient`) في متغير في الـ Sidebar أو في حالة عامة.
- تعديل `updateSaveStatus` لاستخدام ذلك (مثلاً `isLoggedIn` أو `user` مُمرَّر كمعامل)، مع جعل الاستدعاء غير متزامن إذا لزم.

### 3.3 قائمة التصدير المنسدلة المضمنة في الـ HTML غير مستخدمة

**الملف:** `web/index.html`  
**السطور:** 75–122

## 4. المشاكل متوسطة الشدة 🟡

### 4.1 ملفان `vite.config.js` مع إعدادات مختلفة

- **جذر المشروع:** `root: './web'`, `port: 5173`, `resolve.alias`, `server.fs`, `proxy`، ومحاولة `configureServer` داخل `server` (خاطئة).
- **`web/vite.config.js`:** `port: 5174`، `proxy` فقط، بدون `root` ولا `configureServer`.

عند تشغيل `vite` من جذر المشروع يُستخدم `vite.config.js` الجذر. `web/vite.config.js` يُستخدم فقط إذا شُغّل Vite من داخل `web/`.

**التوصية:**  
توحيد الإعداد في مكان واحد (الجذر) وتحديد ما إذا `web/vite.config.js` لسيناريو مختلف (مثلاً اختبار)؛ إن لم يكن ضرورياً، يُفضّل حذفه أو توثيقه بوضوح.

### 4.2 `index.html` في الجذر يعيد التوجيه إلى `/web/`

**الملف:** `index.html` (الجذر)  
**السطور:** 6، 18، 21

- `meta refresh` إلى `url=/web/` ورابط `href="/web/"` ونص يُشير إلى `http://localhost:5173/web/`.

**الملف:** `web/index.html`

### 5.4 `DataService` — مسار استيراد `runFullModel`

**الملف:** `web/js/services/DataService.js`  
**السطر:** 6

```js
import { runFullModel } from '../../../lib/calc/financialModel.js';
```

من `web/js/services/` المسار `../../../lib` يصادف جذر المشروع ثم `lib`، وهذا صحيح عندما يكون جذر المشروع أعلى من `web/`. مع `resolve.alias` في Vite للـ `lib`، يُفضل التأكد من أن الـ alias لا يغيّر سلوك هذا الاستيراد. إن كان الـ alias يُستخدم في أماكن أخرى فقط، لا حاجة لتعديل؛ يُكتفى بمراقبة أي أخطاء في المسارات عند تغيير هيكل المجلدات.

## 7. ملاحظات إضافية

- **CSP في `index.html`:** السياسة محددة بوضوح وتتضمن `'unsafe-inline'` و`'unsafe-eval'` لـ scripts؛ من المفيد مراجعتها على المدى البعيد لتشديد الأمان.
- **Chart.js و jspdf و html2canvas و ExcelJS:** محمّلة من CDN في `index.html`. التأكد من وجود أرقام إصدارات ثابتة أو SRI عند الرغبة في تثبيت إصدارات محددة.
- **`store`:** آلية النسخ الاحتياطي والـ backup في `store` ومحاولة فك التشفير مناسبة؛ يُراعى فقط عدم الاعتماد على `save()` وحده قبل `reload` دون `flush` في مسار تحميل الملف.
