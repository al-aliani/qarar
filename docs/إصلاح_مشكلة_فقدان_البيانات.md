# إصلاح مشكلة فقدان البيانات في الحسابات

**التاريخ:** 2026-01-26  
**المشكلة:** البيانات المدخلة في بعض الصفحات تختفي عند التنقل، مما يؤدي إلى حسابات خاطئة.

---

## 🔍 تحليل المشكلة

### الأسباب المحتملة:

1. **مشكلة في المراجع (References):**
   - عند تحديث البيانات في `DynamicTable`، يتم تمرير مرجع مباشر للـ array
   - عند حفظ البيانات في Store، قد يتم حفظ المرجع بدلاً من نسخة من البيانات
   - عند إعادة تحميل الصفحة، قد يتم استرجاع مرجع قديم

2. **مشكلة في التوقيت:**
   - عند التنقل بين الصفحات، يتم استدعاء `renderStep` الذي يجلب البيانات من Store
   - إذا كان هناك تأخير في الحفظ، قد يتم جلب بيانات قديمة

3. **مشكلة في `updatePath`:**
   - عند تحديث الجداول، يتم استدعاء `updatePath` مع مسار نسبي
   - قد لا يتم حفظ البيانات بشكل صحيح في المسار المحدد

---

## ✅ الإصلاحات المطبقة

### 1. إصلاح `DynamicTable.js` - استخدام Deep Copy

**المشكلة:** عند استدعاء `onChange`، يتم تمرير مرجع مباشر للـ array.

**الحل:** استخدام `JSON.parse(JSON.stringify())` لإنشاء نسخة عميقة من البيانات قبل تمريرها.

**الملفات المعدلة:**
- `web/js/ui/DynamicTable.js`:
  - في `bindEvents` (تحديث خلية)
  - في `addRow` (إضافة صف)
  - في `deleteRow` (حذف صف)
  - في `handleSuggest` (إضافة اقتراحات)

```javascript
// قبل:
this.onChange(this.data);

// بعد:
const dataCopy = JSON.parse(JSON.stringify(this.data));
this.onChange(dataCopy);
```

---

### 2. إصلاح `store.js` - Deep Copy عند الحفظ

**المشكلة:** عند حفظ البيانات في `localStorage`، قد يتم حفظ مراجع بدلاً من القيم.

**الحل:** استخدام Deep Copy قبل الحفظ.

**الملفات المعدلة:**
- `web/js/core/store.js`:
  - في `saveLocal()`:

```javascript
saveLocal() {
    if (!this.state) {
        console.error('Cannot save: state is null');
        return;
    }
    try {
        // Deep clone before saving to prevent reference issues
        const stateToSave = JSON.parse(JSON.stringify(this.state));
        localStorage.setItem(STORAGE_KEY, JSON.stringify(stateToSave));
    } catch (e) {
        console.error('Failed to save to localStorage:', e);
    }
}
```

---

### 3. إصلاح `Wizard.js` - جلب بيانات محدثة

**المشكلة:** عند `renderStep`، يتم جلب البيانات مرة واحدة في البداية، وقد لا تعكس التحديثات الأخيرة.

**الحل:**
- إضافة تحقق من وجود القسم في Store
- إعادة جلب البيانات قبل عرض الجداول

**الملفات المعدلة:**
- `web/js/ui/Wizard.js`:
  - في `renderStep()`: إضافة تحقق من وجود القسم
  - في نهاية `renderStep()`: إعادة جلب البيانات قبل عرض الجداول

```javascript
// إعادة جلب البيانات قبل عرض الجداول
const freshStudyData = this.store.get();
tablesToRender.forEach(tableKey => {
    this.renderTable(stepId, tableKey, freshStudyData);
});
```

## 🧪 كيفية الاختبار

1. **افتح صفحة تحتوي على جدول** (مثل "الموارد البشرية" أو "التجهيزات")
2. **أدخل بيانات في الجدول** (مثل: اسم، عدد، سعر)
3. **انتقل إلى صفحة أخرى** ثم **ارجع إلى نفس الصفحة**
4. **تحقق من أن البيانات لا تزال موجودة**

## 📝 ملاحظات إضافية

### إذا استمرت المشكلة:

1. **افتح Console في المتصفح** (F12) وابحث عن:
   - `console.error` أو `console.warn` متعلقة بـ Store
   - رسائل "Invalid section" أو "Cannot update path"

2. **تحقق من localStorage:**
   ```javascript
   // في Console
   const data = JSON.parse(localStorage.getItem('mac_blash_study_v2'));
   console.log(data);
   ```

3. **تحقق من أن القسم موجود:**
   ```javascript
   // في Console
   const store = window.studyStore;
   const state = store.get();
   console.log('Sections:', Object.keys(state));
   ```
