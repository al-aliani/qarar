## 3. خطة التنفيذ التفصيلية

### المرحلة 1: التصدير المتقدم (أسبوع 1-2)

#### 3.1 PowerPoint Export (PPTX) ⭐⭐⭐⭐⭐

**الهدف:** تصدير دراسة الجدوى كعرض تقديمي احترافي من 10-15 شريحة.

**المكتبة:** `pptxgenjs` (MIT License)

**الشرائح المقترحة:**
1. **غلاف**: اسم المشروع + الشعار + التاريخ
2. **الملخص التنفيذي**: المشكلة، الحل، الفرصة
3. **السوق المستهدف**: الحجم، النمو، الشرائح
4. **الميزة التنافسية**: SWOT مبسط
5. **نموذج الإيرادات**: مصادر الدخل، التسعير
6. **الخطة التشغيلية**: الموقع، المعدات، الفريق
7. **التوقعات المالية**: الإيرادات والأرباح (5 سنوات) - رسم بياني
8. **المؤشرات المالية**: NPV, IRR, Payback Period, ROI
9. **السيناريوهات**: Base, Best, Worst - جدول مقارنة
10. **المخاطر والتوصية**: أهم 3 مخاطر + التوصية النهائية

**الملفات المطلوبة:**
- `web/export/pptxExporter.js` (جديد)
- تحديث `web/js/ui/ExportOptions.js`
- إضافة زر "تصدير PowerPoint" في لوحة القرار

**الاختبار:**
- تصدير دراسة كاملة
- فتح الملف في PowerPoint/Google Slides
- التحقق من الرسوم البيانية والجداول

---

#### 3.2 Word Export (DOCX) ⭐⭐⭐⭐⭐

**الهدف:** تصدير تقرير نصي كامل من 20-30 صفحة قابل للتعديل.

**المكتبة:** `docx` (MIT License)

**محتوى التقرير:**
1. **صفحة الغلاف**
2. **فهرس المحتويات** (تلقائي)
3. **الملخص التنفيذي** (صفحة واحدة)
4. **القسم 1: معلومات المشروع**
   - الاسم، النوع، الموقع، الجهة المنفذة
5. **القسم 2: الدراسة السوقية**
   - تحليل السوق، الشرائح المستهدفة
   - دراسة المنافسين
   - SWOT Analysis
6. **القسم 3: الدراسة الفنية والتشغيلية**
   - الموقع والبنية التحتية
   - المعدات والآلات
   - العمالة والهيكل التنظيمي
7. **القسم 4: الدراسة المالية**
   - هيكل التمويل
   - التكاليف الرأسمالية والتشغيلية
   - الإيرادات والأرباح المتوقعة
8. **القسم 5: التحليل المالي**
   - المؤشرات المالية
   - قوائم مالية (دخل، تدفقات، ميزانية)
   - تحليل الحساسية
9. **القسم 6: المخاطر**
   - المخاطر الرئيسية وخطط التخفيف
10. **القسم 7: التوصية النهائية**
11. **الملاحق**
    - الافتراضات التفصيلية
    - جداول إضافية

**الملفات المطلوبة:**
- `web/export/docxExporter.js` (جديد)
- تحديث `web/js/ui/ExportOptions.js`
- قوالب تنسيق Word (عناوين، فقرات، جداول)

**الاختبار:**
- تصدير دراسة كاملة
- فتح الملف في Word/Google Docs
- التحقق من الجداول والتنسيق

---

#### 3.3 QR Code للمشاركة ⭐⭐⭐⭐⭐

**الهدف:** توليد QR code لمشاركة رابط الدراسة بسرعة.

**المكتبة:** `qrcode` (MIT License)

**السيناريو:**
1. المستخدم يضغط على "مشاركة" → "QR Code"
2. النظام يولّد رابط مشاركة (مثلاً: `https://app.feasibility.sa/share/{studyId}`)
3. عرض QR code + خيار تحميله كصورة PNG
4. أي شخص يمسح الكود → يفتح ملخص الدراسة (للمشاريع العامة أو المشاركة)

**الملفات المطلوبة:**
- `web/js/utils/qrGenerator.js` (جديد)
- تحديث `web/js/utils/shareUtils.js`
- UI modal لعرض QR code

**الأمان:**
- رابط المشاركة يتطلب token
- يمكن تعطيل المشاركة في أي وقت
- خيار مشاركة للقراءة فقط (read-only)

**الاختبار:**
- توليد QR code
- مسح الكود بالهاتف
- التحقق من فتح الدراسة

### المرحلة 2: إدارة المشاريع المتقدمة (أسبوع 3)

#### 3.4 نسخ مشروع (Duplicate) ⭐⭐⭐⭐

**الهدف:** استنساخ دراسة موجودة كنقطة بداية لمشروع جديد.

**السيناريو:**
- المستخدم لديه دراسة جدوى لمقهى في الرياض
- يريد فتح فرع ثانٍ في جدة
- يضغط "نسخ المشروع" → يُنشأ مشروع جديد بنفس الهيكل
- يعدّل الموقع والأرقام حسب السوق الجديد

**الميزات:**
- نسخ كل البيانات (أو اختيار أقسام معينة)
- تسمية تلقائية: "نسخة من [اسم المشروع]"
- خيار: نسخ بالبيانات أم بالهيكل فقط

**الملفات المطلوبة:**
- تحديث `web/js/services/DataService.js` → `duplicateStudy(studyId, options)`
- زر "نسخ" في قائمة المشاريع
- UI modal لتأكيد النسخ

**الاختبار:**
- نسخ مشروع كامل
- التحقق من استقلالية المشروع الجديد
- تعديل النسخة دون تأثير على الأصل

---

#### 3.5 سلة المحذوفات ⭐⭐⭐⭐

**الهدف:** حماية من الحذف العرضي مع إمكانية الاسترجاع.

**الآلية:**
- عند الحذف → نقل إلى سلة المحذوفات (soft delete)
- الاحتفاظ لمدة 30 يوماً
- بعد 30 يوم → حذف نهائي تلقائي (hard delete)
- المستخدم يمكنه استرجاع أو حذف نهائياً يدوياً

**السكيم (Supabase):**
```sql
ALTER TABLE feasibility_studies 
ADD COLUMN deleted_at TIMESTAMP DEFAULT NULL;

-- Soft delete
UPDATE feasibility_studies 
SET deleted_at = NOW() 
WHERE id = '...';

-- Restore
UPDATE feasibility_studies 
SET deleted_at = NULL 
WHERE id = '...';
```

**الملفات المطلوبة:**
- تحديث `web/js/services/DataService.js`
- صفحة جديدة: `web/js/ui/TrashView.js`
- إضافة عمود `deleted_at` في جدول `feasibility_studies`

**الاختبار:**
- حذف مشروع → يظهر في السلة
- استرجاع → يعود للقائمة الرئيسية
- انتظار 30 يوم (محاكاة) → حذف نهائي

---

#### 3.6 إرسال بالبريد مباشرة ⭐⭐⭐⭐

**الهدف:** إرسال ملخص الدراسة أو التقرير كاملاً للمستثمرين/الشركاء.

**الخيارات:**
1. **EmailJS** (مجاني - 200 إيميل/شهر)
   - سهل التكامل
   - لا يتطلب backend
   - مناسب للنسخة الأولى

2. **Supabase Edge Functions + Resend API** (احترافي)
   - تحكم كامل
   - إمكانية إرفاق ملفات
   - تتبع الإرساليات

**السيناريو:**
- المستخدم يضغط "إرسال بالبريد"
- يُدخل إيميل المستلم + رسالة اختيارية
- يختار: ملخص تنفيذي أم تقرير كامل (PDF)
- النظام يرسل الإيميل بالتقرير مرفقاً

**الملفات المطلوبة:**
- `web/js/services/EmailService.js` (جديد)
- UI modal لإرسال البريد
- قالب إيميل HTML احترافي

**الأمان:**
- تحديد عدد الإرساليات (5 إيميلات/يوم للمستخدم المجاني)
- حماية من spam
- تشفير المرفقات الحساسة

### المرحلة 3: Analytics والأمان (أسبوع 4)

#### 3.7 Analytics (GA4/Mixpanel) ⭐⭐⭐

**الهدف:** فهم سلوك المستخدمين لتحسين المنصة.

**الأحداث المطلوب تتبعها:**

| الحدث | الوصف | البيانات |
|-------|-------|----------|
| `page_view` | فتح صفحة | الصفحة، الوقت |
| `study_created` | إنشاء دراسة جديدة | القطاع، القالب |
| `step_completed` | إكمال خطوة من Wizard | رقم الخطوة، الوقت المستغرق |
| `export_pdf` | تصدير PDF | حجم الدراسة، الوقت |
| `export_excel` | تصدير Excel | - |
| `export_pptx` | تصدير PowerPoint | - |
| `export_docx` | تصدير Word | - |
| `share_qr` | توليد QR code | - |
| `study_duplicated` | نسخ مشروع | - |
| `ai_suggestion_used` | استخدام اقتراح AI | النوع |

**الاختيار: GA4 vs Mixpanel**

| المعيار | Google Analytics 4 | Mixpanel |
|---------|-------------------|----------|
| **السعر** | مجاني | مجاني حتى 100K حدث/شهر |
| **سهولة التكامل** | سهل جداً | متوسط |
| **التحليلات** | عامة | متقدمة (funnel, cohorts) |
| **الخصوصية** | يتطلب cookie consent | أفضل |

**التوصية:** **GA4** للبداية (سهل + مجاني)، **Mixpanel** لاحقاً للتحليلات المتقدمة.

**الملفات المطلوبة:**
- `web/js/utils/analytics.js` (جديد)
- تحديث `web/index.html` (GA4 script)
- إضافة tracking لكل الأحداث الرئيسية

**الخصوصية:**
- سياسة خصوصية محدّثة
- موافقة المستخدم على tracking
- خيار إيقاف التتبع

#### 3.8 سجل تسجيلات الدخول ⭐⭐⭐

**الهدف:** عرض تاريخ الدخول للمستخدم (أمان + شفافية).

**المعلومات المعروضة:**
- التاريخ والوقت
- الجهاز (Desktop / Mobile)
- المتصفح
- الموقع التقريبي (المدينة)
- عنوان IP (مخفي جزئياً: `192.168.*.***`)

**السكيم (Supabase):**
```sql
CREATE TABLE user_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  login_at TIMESTAMP DEFAULT NOW(),
  device_type TEXT, -- desktop, mobile, tablet
  browser TEXT,
  ip_address TEXT,
  location_city TEXT,
  location_country TEXT
);
```

**الملفات المطلوبة:**
- صفحة جديدة: `web/js/ui/SecuritySettingsView.js`
- تحديث `web/supabaseClient.js` لتسجيل الدخول
- UI table لعرض السجل

**الميزات الإضافية:**
- خيار "إنهاء كل الجلسات الأخرى" (logout من كل الأجهزة)
- تنبيه عند دخول من جهاز جديد
- الاحتفاظ بالسجل لمدة 90 يوماً

### المرحلة 4: التكاملات الخارجية (أسبوع 5-6)

#### 3.9 Zapier Integration ⭐⭐

**الهدف:** ربط المنصة بـ 5000+ تطبيق (Gmail, Slack, Notion, Trello...).

**السيناريوهات:**
- **إنشاء دراسة جديدة** → إرسال إشعار في Slack
- **تصدير تقرير** → حفظ في Google Drive تلقائياً
- **مشروع جاهز** → إضافة مهمة في Trello

**الطريقة:**
1. **Webhooks** (الأسهل)
   - عند حدث معين → إرسال HTTP POST لـ Zapier
   - Zapier يستقبل البيانات ويوزعها

2. **Zapier Platform** (احترافي)
   - بناء تكامل رسمي في Zapier
   - يتطلب وقت أطول + موافقة Zapier

**التوصية:** البداية بـ **Webhooks** (أسرع)، ثم تطوير تكامل رسمي.

**الملفات المطلوبة:**
- `web/js/services/WebhookService.js` (جديد)
- إعدادات Zapier في لوحة المستخدم
- توثيق (كيف تربط المنصة بـ Zapier)

**الأحداث المقترحة:**
- `study.created`
- `study.completed`
- `report.exported`
- `decision.go` / `decision.nogo`

---

#### 3.10 Notion Integration ⭐⭐

**الهدف:** تصدير دراسة الجدوى إلى Notion كصفحة منظمة.

**المكتبة:** `@notionhq/client` (Official Notion SDK)

**السيناريو:**
- المستخدم يربط حسابه في Notion (OAuth)
- يختار workspace/database في Notion
- يضغط "تصدير إلى Notion"
- تُنشأ صفحة جديدة بكامل الدراسة

**التحديات:**
- Notion API محدود (لا يدعم رسوم بيانية مباشرة)
- يتطلب OAuth flow
- قد يكون معقداً للمستخدم العادي

**التوصية:** **أولوية منخفضة** - يمكن تأجيلها حتى يطلبها المستخدمون.

**البديل الأسهل:** تصدير Markdown + نسخ إلى Notion يدوياً.
