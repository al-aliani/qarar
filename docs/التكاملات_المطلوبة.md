# التكاملات المطلوبة في الموقع

## ملخص

المنصة تعمل **بدون أي تكامل خارجي** (وضع محلي): المسودة تُحفظ في المتصفح، والتصدير يعمل، وواجهة المستخدم كاملة.

التكاملات التالية **اختيارية** لتحسين التجربة:

| التكامل | مطلوب؟ | الوظيفة | إذا لم يُهيَّأ |
|---------|--------|---------|-----------------|
| **Supabase** | اختياري | المصادقة + الحفظ السحابي للمشاريع | الحفظ محلي فقط (localStorage) |
| **تسجيل الدخول بـ Google** | اختياري | OAuth عبر Supabase | يُفعّل من Supabase → Providers → Google |
| **خادم AI (localhost:8080)** | اختياري | توليد نصوص بالذكاء الاصطناعي (ملخص، Pitch Script، إلخ) | مولّد داخلي (InternalAIGenerator) |
| **Google Sheets** | اختياري | تصدير إلى جداول Google | إعداد من: حسابي → التكاملات، أو من قائمة التصدير |
| **reCAPTCHA v3** | اختياري | حماية نموذج الدخول من البوتات | إعداد من: حسابي → التكاملات (Site Key) |

**صفحة التكاملات في الواجهة:** بعد تسجيل الدخول → **حسابي** → **التكاملات**. تعرض حالة كل تكامل (مفعّل / غير مهيأ) وحقول الإعداد (Google Sheets URL، reCAPTCHA Site Key).

## إصلاح خطأ 500 على PersistenceService.js

إذا ظهر:

```text
GET http://localhost:5173/js/services/PersistenceService.js?t=... net::ERR_ABORTED 500 (Internal Server Error)
```

**السبب المحتمل:** تحميل الملف كان يفشل عند استيراد Supabase أو سجل التدقيق (auditLogger) قبل تهيئة البيئة.

**ما تم تطبيقه:** تحويل استيراد `supabaseClient.js` و `auditLogger.js` إلى **استيراد ديناميكي** داخل `PersistenceService.js`. بذلك:

- الملف يُحمَّل بنجاح (200) حتى بدون Supabase.
- عند استدعاء الحفظ/التحميل، إن وُجد Supabase يُستخدم، وإلا يعمل الحفظ المحلي فقط.

**ما تفعله أنت:**

1. حدّث الكود (التعديلات أعلاه مُطبَّقة في المشروع).
2. أعد تشغيل خادم التطوير: `npm run dev`.
3. حدّث الصفحة (Ctrl+F5 أو إعادة تحميل قوية).

إن استمر الخطأ:

- تأكد أنك تشغّل من جذر المشروع وأن `vite.config.js` يستخدم `root: './web'`.
- تأكد أن الملف `web/js/services/PersistenceService.js` موجود وأن لا أخطاء في Console عند تحميل الصفحة.

## تفعيل Supabase (اختياري)

للحفظ السحابي والمصادقة:

1. اتبع **[إعداد Supabase](إعداد_Supabase.md)**.
2. ضع `SUPABASE_URL` و `SUPABASE_ANON_KEY` في localStorage أو في متغيرات البيئة حسب الوثيقة.
3. أنشئ الجداول من **docs/supabase_schema.sql** في SQL Editor بمشروع Supabase.

بعدها يعمل `PersistenceService` تلقائياً مع السحابة عند تسجيل الدخول.

---

## تفعيل خادم AI (اختياري)

لتوليد نصوص بالذكاء الاصطناعي من الخادم:

```bash
python ai_server.py
```

يعمل الخادم على `http://localhost:8080`. الواجهة تتصل به تلقائياً؛ إن لم يكن يعمل، يُستخدم المولّد الداخلي.

## أولوية متوسطة (مخطط)

التكاملات التالية **مخططة** وتظهر في صفحة التكاملات (حسابي → التكاملات) تحت «أولوية متوسطة»:

| التكامل | الوظيفة المقترحة | ملاحظات |
|---------|------------------|---------|
| **Zapier Webhook** | ربط المنصة بـ 5000+ تطبيق عبر Webhooks | أحداث: دراسة جديدة، تصدير تقرير، قرار GO/NO-GO. راجع docs/INTEGRATION_FEATURES.md (WebhookService). |
| **Slack Notifications** | إشعارات في قناة Slack | عند إكمال دراسة، تصدير، أو قرار استثماري. يمكن تنفيذه عبر Webhook واحد يوجّه لـ Slack Incoming Webhook. |
| **Email Automation** | أتمتة إرسال التقارير أو التذكيرات | EmailJS أو Resend أو Supabase Edge Functions. راجع docs/INTEGRATION_FEATURES.md (EmailService). |
| **Analytics (Mixpanel)** | تتبع الأحداث والسلوك | تسجيل، إنشاء دراسة، تصدير، قرار. يتطلب موافقة المستخدم (GDPR). راجع GA4 في INTEGRATION_FEATURES.md كمرجع. |
| **QuickBooks** | ربط البيانات المالية أو التصدير مع QuickBooks | يتطلب OAuth وواجهة برمجية QuickBooks؛ جهد أكبر من باقي التكاملات. |

عند التنفيذ: ابدأ بـ **Zapier Webhook** (يعمم على Slack وغيره)، ثم **Email Automation**، ثم **Analytics**، ثم **QuickBooks** حسب الحاجة.
