## الفئة 1: تحسين المستودع عبر GitHub (Smart Repositories)

### س1.1 — "طيب، تعرف محركات المشروع صح؟ كيف أننا نستفيد من مستودعات ذكية في قيت هب؟ + حنا وش نحتاج؟"

**طريقة الإجابة:** شرح مفاهيمي عام (بدون فحص كود بعد) لمكوّنات "المستودع الذكي" في GitHub.

**الإجابة:** شرحت أن GitHub بيئة متكاملة لا مجرد مخزن كود، وأن "الذكاء" يأتي من: الأتمتة (GitHub Actions/CI-CD)، الحراسة الأمنية (Dependabot، Secret Scanning)، إدارة المشاريع المدمجة (GitHub Projects)، التوحيد القياسي (Issue/PR Templates)، ودمج الذكاء الاصطناعي (Copilot).

**المقترحات:**

- ملف `README.md` احترافي
- ملف `.gitignore`
- هيكلة مجلدات واضحة (docs/, frontend/, backend/)
- حماية الفرع الرئيسي (Branch Protection)
- لوحة مهام (GitHub Project Board)
- تحديد التقنيات لأتمتة CI مناسبة

### س1.2 — "أبدأ نفذ"

**طريقة الإجابة:** فحص فعلي للمستودع (اكتشاف Node.js/Vite + Python + إعدادات اختبارات موجودة)، ثم خطة تنفيذ فعلية.

**الإجابة/التنفيذ:** أُنشئت فعلياً داخل `.github/`:

- `dependabot.yml` — تحديثات تلقائية للتبعيات
- `ISSUE_TEMPLATE/bug_report.md` و `feature_request.md`
- `PULL_REQUEST_TEMPLATE.md`
- `workflows/ci.yml` — يشغّل `npm test` و`npm run lint` و`pytest` تلقائياً

**المقترحات:** تفعيل يدوي من إعدادات GitHub لـ"Require a pull request before merging" على الفرع `main` (لم يُنفَّذ برمجياً، يحتاج إجراء المستخدم بنفسه في واجهة GitHub).

## الفئة 3: تحمّل المنصة لمليون مستخدم

### س3.1 — "الموقع يتحمل مليون مستخدم؟"

**طريقة الإجابة:** شرح معماري تعليمي (بدون تنفيذ — سؤال معرفي بحت).

**الإجابة:** لا، ليس بالوضع المحلي الحالي (`localhost`)، لكن المعمارية (React + Supabase + Celery) قابلة للتوسّع إذا نُشرت صح:

- **الواجهة الأمامية:** جاهزة فعلياً — تُنشر على CDN (Cloudflare/Vercel/AWS CloudFront)
- **قاعدة البيانات:** تحتاج Connection Pooling (Supavisor) وفهرسة
- **الخلفية (Python/AI):** أكبر عنق زجاجة — تحتاج Gunicorn/Uvicorn، توسيع أفقي (Load Balancer)، Cache عبر Redis
- **المهام الخلفية:** Celery (مؤسَّس مسبقاً) يمنع تعليق الموقع عند الضغط

**المقترحات:** لا مستودعات جديدة هنا — توصيات DevOps/نشر (AWS/GCP، Load Balancer، CDN).
